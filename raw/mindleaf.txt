## 1. Product Vision

Most people own 10+ books they've never finished. MindLeaf solves the gap between intention and execution — delivering the highest-signal, most transformative ideas from the world's best self-development books through beautifully crafted markdown summaries, bite-sized flashcards, and visual lessons powered by Cloudinary-hosted images and GIFs.

> **"Read less. Absorb more. Become the 1% who actually acts on what they read."**

MindLeaf is not a library. It is not a bookstore. It is a **curated knowledge absorption system** — 10 books, zero filler, stunning visuals, and a habit layer that keeps you coming back.

### Problem Statement

- Most people start books but never finish them
- Key insights are buried in 300+ pages of context
- Existing summary apps (Blinkist) are expensive, generic, and visually poor
- No app combines summaries + structured lessons + visual flashcards in one place

### Solution

A premium mobile reading app with:
- Full markdown-rendered book summaries
- Lesson modules broken into digestible chapters
- Flashcard decks with GIF/image visual examples on every card
- Streak and progress gamification to build a reading habit

---

## 2. Target Audience

**Primary:** Ambitious 18–35 year olds — students, early professionals, builders — who want to absorb the world's best ideas but lack time to read full books.

**Psychographic:** The top 1% mindset. People who watch self-development content, follow Naval/Goggins/Huberman, and believe in compounding personal growth.

**Secondary:** College students preparing for life post-graduation, wanting mental models and frameworks before entering the real world.

### Content Structure Per Book

Every book in MindLeaf follows the same structure:

```
Book
├── Cover Image (Cloudinary)
├── Big Idea Quote (shareable one-liner)
├── Key Takeaways (3–5 bullet insights)
├── Full Summary (Markdown, chapter-aware)
```

## 4. Core Features

### 4.1 Markdown Summary Reader

Full markdown-rendered book summaries with chapter-wise navigation.

**Details:**
- Renderer: `react-native-markdown-display` with custom style overrides via NativeWind
- Chapter progress stored locally in MMKV, synced to MongoDB
- Font size control (S / M / L)
- Line height control
- Reader themes: Light / Dark / Sepia
- Estimated read time displayed per chapter
- Pull-to-refresh for content updates
- Long-press on any paragraph → highlight menu

### 4.2 Flashcard Decks

Spaced-repetition ready flashcard decks — one deck per book with 10–20 cards.

**Details:**
- Swipe right = Mastered, Swipe left = Review again
- Card flip animation via `react-native-reanimated`
- Front: concept title + question text
- Back: insight markdown + optional Cloudinary image or GIF
- Per-book mastery ring (% of cards mastered)
- Daily flashcard goal (configurable: 5 / 10 / 20 cards)
- Streak bonus for completing daily flashcard goal

**GIF usage on flashcards:**
- Habit loop (Atomic Habits) → animated cue → routine → reward cycle
- System 1 vs System 2 thinking (Thinking Fast & Slow) → animated brain diagram
- Compound interest visual (Psychology of Money) → animated growth curve

### 4.3 Lessons Module

Each book broken into 5–8 standalone lessons. More structured than the summary, more focused than the full book.

**Details:**
- Lesson list screen with per-lesson progress state (not started / in progress / completed)
- Each lesson has: title, markdown body, inline Cloudinary media, and a Key Action at the end
- Completion ticks the lesson in the user's progress map
- Completing all lessons for a book unlocks a "Book Mastered" badge
- `Key Action` is a single sentence the user is meant to take in the next 24 hours

### 4.4 Key Takeaways

The first thing shown when you open a book — before you read a word of the summary.

**Details:**
- Big Idea: one-liner quote from the book (displayed prominently, Playfair Display font)
- Top 3–5 distilled insights as a numbered list
- "Share" button on the Big Idea → generates a 1080×1080 Cloudinary-transformed share card
- Share card includes: book title, quote, author, and MindLeaf branding

### 4.5 Highlights & Personal Notes

Long-press any paragraph in the summary or a lesson to highlight it.

**Details:**
- 4 highlight colors: Yellow, Green, Blue, Pink
- Tap highlighted text to add a personal note
- All highlights + notes saved to MongoDB per user
- Highlights screen (`/highlights`) shows all highlights across all books, grouped by book
- Export all notes as plain text (share sheet)

### 4.6 Streak & Progress System

The habit layer on top of reading — because consistency beats intensity.

**Details:**
- Daily reading streak counter (incremented by any reading activity)
- `lastActiveDate` stored on user document, streak resets if gap > 1 day
- Streak milestones: 3 days, 7 days, 21 days, 66 days (with badge unlocks)
- Books absorbed counter on profile
- Weekly reading goal (configurable: 1 / 2 / 3 summaries per week)
- Push notification reminder (configurable time via `expo-notifications`)

### 4.7 Personal Library

**Details:**
- Three shelves: Want to Read / In Progress / Completed
- Auto-moves to Completed when both summary + all lessons are marked done
- Recently accessed row on Home screen
- Recommended next book based on matching tags

### 4.8 Visual Media (Cloudinary)

All images and GIFs are hosted on Cloudinary and served via Next.js API proxy.

**Details:**
- Every lesson has at least one visual asset
- GIFs are used wherever a concept is easier shown than described
- Named transformations control size per context (see Section 9)
- `expo-image` used for rendering — supports WebP, blurhash placeholders, caching

## 6. Data Models — MongoDB Schema

### `books` collection

```typescript
{
  _id: ObjectId,
  slug: string,               // "atomic-habits" — unique URL key
  title: string,
  author: string,
  coverImageId: string,       // Cloudinary public_id
  tags: string[],             // ["systems", "habits", "behavior"]
  readTimeMinutes: number,    // estimated full summary read time
  bigIdea: string,            // one-liner quote for share card
  takeaways: string[],        // 3–5 key insights (plain text)
  summaryMarkdown: string,    // full markdown content
  chapters: [
    {
      title: string,
      anchorId: string,       // used for chapter nav
      readTimeMinutes: number
    }
  ],
  totalLessons: number,       // denormalized count
  totalFlashcards: number,    // denormalized count
  publishedAt: Date,
  updatedAt: Date
}
```

### `lessons` collection

```typescript
{
  _id: ObjectId,
  bookId: ObjectId,           // ref: books
  bookSlug: string,           // denormalized for query convenience
  order: number,              // display sequence (1-indexed)
  title: string,
  bodyMarkdown: string,       // markdown with ![alt](cloudinary_url) inline
  mediaAssets: [
    {
      type: 'image' | 'gif',
      cloudinaryId: string,
      caption: string,
      transformName: string   // named transformation to apply
    }
  ],
  keyAction: string,          // one actionable step shown at lesson end
  readTimeMinutes: number,
  createdAt: Date
}
```

### `flashcards` collection

```typescript
{
  _id: ObjectId,
  bookId: ObjectId,           // ref: books
  bookSlug: string,
  order: number,
  front: string,              // concept title or question
  back: string,               // insight markdown (can include formatting)
  backMediaId: string | null, // Cloudinary public_id for image/GIF
  mediaType: 'image' | 'gif' | null,
  createdAt: Date
}
```

### `users` collection

```typescript
{
  _id: ObjectId,
  deviceId: string,           // Expo Constants.deviceId (no-auth MVP)
  streak: number,
  lastActiveDate: Date,
  weeklyGoal: number,         // 1 | 2 | 3 summaries/week
  dailyFlashcardGoal: number, // 5 | 10 | 20
  booksWantToRead: ObjectId[],
  booksInProgress: ObjectId[],
  booksCompleted: ObjectId[],
  highlights: [
    {
      bookId: ObjectId,
      paragraphId: string,    // deterministic ID from paragraph content hash
      text: string,           // highlighted text
      color: 'yellow' | 'green' | 'blue' | 'pink',
      note: string | null,
      createdAt: Date
    }
  ],
  flashcardProgress: {
    // key: bookId.toString()
    [bookId: string]: {
      mastered: string[],     // flashcard _id strings
      review: string[]
    }
  },
  readingProgress: {
    // key: bookId.toString()
    [bookId: string]: {
      chapterIndex: number,
      scrollPercent: number,
      lessonsCompleted: string[] // lesson _id strings
    }
  },
  notificationsEnabled: boolean,
  reminderTime: string | null, // "08:00" HH:mm
  theme: 'light' | 'dark' | 'sepia',
  createdAt: Date,
  updatedAt: Date
}
```

### Indexes

```
books:         { slug: 1 }  (unique)
lessons:       { bookId: 1, order: 1 }
flashcards:    { bookId: 1, order: 1 }
users:         { deviceId: 1 }  (unique)
```

## 7. API Design — Next.js Serverless Routes

All routes live under `app/api/` in the Next.js 14 App Router. MongoDB connection via Mongoose with connection pooling in a shared `lib/db.ts`.

### Books

| Method | Route | Description | Response |
|--------|-------|-------------|----------|
| GET | `/api/books` | All books, lightweight (no summaryMarkdown) | `Book[]` (partial) |
| GET | `/api/books/[slug]` | Full book detail including markdown | `Book` (full) |
| GET | `/api/books/[slug]/lessons` | All lessons for a book (no bodyMarkdown) | `Lesson[]` (partial) |
| GET | `/api/books/[slug]/lessons/[id]` | Single lesson with full markdown + media | `Lesson` (full) |
| GET | `/api/books/[slug]/flashcards` | Full flashcard deck for a book | `Flashcard[]` |

### User

| Method | Route | Description | Body |
|--------|-------|-------------|------|
| POST | `/api/user/init` | Create or fetch user by deviceId | `{ deviceId }` |
| GET | `/api/user/[deviceId]` | Full user profile + progress | — |
| PATCH | `/api/user/progress` | Update reading/lesson progress + streak | `{ deviceId, bookId, progress }` |
| PATCH | `/api/user/flashcards` | Update mastered/review sets | `{ deviceId, bookId, masteredIds, reviewIds }` |
| PATCH | `/api/user/library` | Move book between shelves | `{ deviceId, bookId, shelf }` |
| POST | `/api/user/highlights` | Save a new highlight + optional note | `{ deviceId, highlight }` |
| PATCH | `/api/user/highlights/[id]` | Edit note on existing highlight | `{ note }` |
| DELETE | `/api/user/highlights/[id]` | Delete a highlight | — |
| GET | `/api/user/highlights` | All highlights for a user | `?deviceId=` |
| PATCH | `/api/user/settings` | Update theme, notification, goal settings | `{ deviceId, settings }` |

### Media

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/api/media/[cloudinaryId]` | Return signed Cloudinary URL for private assets |

### Streak Logic (server-side in PATCH /user/progress)

```typescript
const today = new Date().toDateString();
const lastActive = new Date(user.lastActiveDate).toDateString();
const yesterday = new Date(Date.now() - 86400000).toDateString();

if (lastActive === today) {
  // same day — no change to streak
} else if (lastActive === yesterday) {
  // consecutive day — increment streak
  user.streak += 1;
} else {
  // gap — reset streak
  user.streak = 1;
}
user.lastActiveDate = new Date();
```

## 9. Cloudinary Media Strategy

All visual assets are uploaded to Cloudinary once and referenced by `public_id` in MongoDB. The Next.js API proxies signed URLs so API secrets never reach the client.

### Folder Structure on Cloudinary

```
mindleaf/
├── covers/          → book cover images
├── lessons/         → lesson inline images
├── flashcards/      → flashcard back images + GIFs
└── share/           → pre-generated share card templates
```

### Named Transformations

Create these in the Cloudinary dashboard under Settings > Upload > Named Transformations:

| Name | Transformation | Used In |
|------|---------------|---------|
| `book_cover_card` | `w_200,h_280,c_fill,q_auto,f_webp` | BookCard, Discover grid |
| `book_cover_hero` | `w_400,h_560,c_fill,q_auto,f_webp` | Book Detail hero |
| `lesson_media` | `w_720,q_auto,f_auto` | Inline in lesson markdown |
| `flashcard_gif` | `w_480,h_320,c_fill,fl_lossy` | Flashcard back GIF |
| `share_card` | `w_1080,h_1080,c_fill,q_auto` | Share card export |

### Constructing URLs in Next.js

```typescript
import { v2 as cloudinary } from 'cloudinary';

cloudinary.config({
  cloud_name: process.env.CLOUDINARY_CLOUD_NAME,
  api_key: process.env.CLOUDINARY_API_KEY,
  api_secret: process.env.CLOUDINARY_API_SECRET,
});

export function getMediaUrl(publicId: string, transformName: string): string {
  return cloudinary.url(publicId, {
    named_transformation: transformName,
    sign_url: true,
    secure: true,
  });
}
```

## 13. Out of Scope (MVP)

The following are intentionally excluded from v1.0 to keep the scope tight:

- **User authentication** — deviceId is sufficient for MVP; no email/password/OAuth
- **Social features** — no public profiles, followers, or shared highlights
- **In-app purchases / paywall** — free during beta; monetization in v2
- **Search within summary** — full-text search deferred to v2
- **Audio narration** — text-to-speech of summaries deferred
- **Web version** — mobile-only for MVP
- **Admin CMS** — content seeded via scripts, not a dashboard
- **Comments or community** — single-player app for now
- **More than 10 books** — quality over quantity is the core promise
